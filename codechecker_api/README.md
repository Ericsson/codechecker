# CodeChecker server Thrift API

This directory contains the API IDL files and the generated API stubs for
CodeChecker. [Apache Thrift](https://thrift.apache.org/) is used to generate
the stubs for various programming languages (Python, JavaScript).

## API change workflow
- Modify the `.thrift` API files.
- Update the Thrift API version in `api_version.json`.
- Run `make clean` and then `make package` or `make dev_package`
in the root of the repository.

## Generating the stubs
The stubs are generated by a Thrift compiler that runs inside a Docker
container (see [`Dockerfile`](Dockerfile)), so `docker` needs to be installed
on the system.

Running `make package` or `make dev_package` in the root of the repository 
always generates the Thrift stubs.

The stubs are generated to:
- `codechecker_api/python/` (Python)
- `codechecker_api/js/` (Node.js)

directories and NOT tracked in version control.

## API versioning
CodeChecker supports backward compatibility between API versions.

The API version is automatically encoded into the `POST` request URLs made by
Thrift in the following format:

    http://example.com:8001/[product-name]/<API-version>/<API-service>

For example:

    https://example.com:8001/Default/v6.74/CodeCheckerService

The version supported by a build is defined in [`api_version.json`](api_version.json).
A client API request is accepted by the server when its **major** version matches 
the server's major version and its **minor** version is not greater than the server's minor
version.

## Available APIs

### Report server API
The report server API should be used by any client to view or store analysis
results.

API Endpoint: `/<product-name>/<API-version>/CodeCheckerService`

API description: [report_server.thrift](report_server.thrift).

### Authentication system API
The authentication layer is used for supporting privileged-access only access
and permission management.

API Endpoint: `/<API-version>/Authentication`

API description: [authentication.thrift](authentication.thrift).

### Product management system API
The product management layer is responsible for handling requests about the
different products and their configuration.

API Endpoint: `/<API-version>/Products`

API description: [products.thrift](products.thrift).

### Configuration API
The configuration layer is used to set notifications displayed on the server.

API Endpoint: `/<API-version>/Configuration`

API description: [configuration.thrift](configuration.thrift).

### Server information API
The server information layer is used to get the running CodeChecker version,
for API compatibility purposes.

API Endpoint: `/<API-version>/ServerInfo`

API description: [server_info.thrift](server_info.thrift).

### Server-side tasks API
The tasks layer is used to query and manage long-running, server-side
background tasks.

API Endpoint: `/<API-version>/Tasks`

API description: [tasks.thrift](tasks.thrift).

### Other endpoints
`GET` requests made to endpoints `/live` and `/ready` can be used to check the
health of the running server.
